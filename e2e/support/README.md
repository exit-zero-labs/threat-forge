# `e2e/support/`

Shared, versioned test infrastructure consumed by every spec under `e2e/`. Individual specs stay
scenario-specific; this directory holds the cross-spec contracts they build on. See
`docs/plans/65-browser-workspace-fixtures.md` for the full design rationale (D1-D9) — this file is
a map of what lives where and the conventions future issues (`#66`, `#67`) should follow, not a
restatement of that plan's reasoning.

## Modules

- **`base.ts`** — the failure-aware Playwright base every other layer in this directory (and every
  spec, directly or through `e2e/fixtures.ts`) is ultimately built on:
  - `failureAwareTest`/`expect`: a `page` fixture that fails the test if the page emits an
    unallowlisted `console.error`, `console.warning`, `pageerror`, or `requestfailed` event. The
    default allowlist is empty. A test that deliberately triggers a fully understood, safe
    condition opts in narrowly with
    `test.use({ allowedBrowserEvents: [{ channel, pattern }] })`, scoped to that test or `describe`
    block. The channel is part of the exception, so matching text on an error or failed request
    remains disallowed.
  - `installDeterministicClock(page, iso?)`: anchors `Date.now()`/`new Date()` to a fixed instant
    via `page.clock.install`, for any fixture whose seeded content embeds a timestamp.
  - `e2e/fixtures.ts` extends `failureAwareTest`'s `page` fixture with first-run overlay
    suppression and exports the app-specific `test`/`expect`/helpers most ordinary specs import.
    `onboarding-auto-start.spec.ts` is the one exception: it imports `failureAwareTest` directly
    so real first-run behavior stays under test.
- **`interactions.ts`** — typed, `test.step`-wrapped helpers for actions used across more than one
  spec (create/open/switch tabs, drag/connect elements, rename, save/export, wait for a local
  save, open N documents). Promote a helper here when a second spec needs the same interaction
  verbatim; a spec-local one-liner used once stays local (see D6 in the plan for examples of both
  directions).
- **`workspace-fixtures.ts`** — nine versioned functions, one per named browser workspace state
  (empty, realistic, large, malformed, multi-tab, and four recovery states: ephemeral, write
  failure, stale manifest, corrupt sole document). Each function seeds its state and returns once
  it is fully settled. Fixtures 1-5 seed exclusively through the app's own public UI/file
  interfaces; fixtures 6-9 are recovery states with no public-UI equivalent, so they use a
  narrowly scoped test-adapter technique (see each function's doc comment for exactly what it does
  and why). `WORKSPACE_FIXTURE_VERSION` is exported once and included in every fixture's
  `test.step` name.

## Conventions for future issues (`#66`, `#67`)

- **Step naming:** every `test.step` name in this directory follows one of two shapes so a trace
  or report reader (human or a future automated summarizer) can tell a fixture-seeding step from
  an ordinary interaction step at a glance:
  - Fixtures: `` `seed:<name>@v${WORKSPACE_FIXTURE_VERSION}` `` — e.g. `seed:empty@v1`.
  - Interactions: `` `<verb>: <summary>` `` — e.g. `openDocument: open <path> via the Open dialog`.
- **Fixture versioning:** a fixture's *shape* (what it seeds, what state it leaves the app in) is
  covered by `WORKSPACE_FIXTURE_VERSION`. Changing what an existing `seed*` function does is a
  breaking change to anything that depends on it: bump the constant, update the affected
  function's doc comment, and record the change in the relevant plan's Replan log — never silently
  overwrite a fixture's behavior in place.
- **The large `.thf` fixture** (`e2e/fixtures/large-model.thf`) is regenerated by
  `e2e/fixtures/gen-large-model.mjs` (not wired into any npm script — run manually). Do not
  hand-edit the `.thf` file; change the generator and re-run it.
- **Adding a helper or fixture:** extend `interactions.ts`/`workspace-fixtures.ts` in place rather
  than duplicating a create/open/switch/drag/connect pattern inline in a new spec. If a genuinely
  new *class* of workspace state is needed, add a tenth `seed*` function and a corresponding
  discriminating test in `e2e/workspace-fixtures.spec.ts`, rather than overloading an existing one.
